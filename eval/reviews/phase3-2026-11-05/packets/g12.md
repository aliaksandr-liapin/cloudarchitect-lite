# Review packet, group 12

Scenarios in this packet: brochure-site, k8s-microservices, regulated-portal. Read `reviewer-instructions.md` for the task and the output format.

## Rubric

Score each design on seven dimensions, each 0-3 (0 = critical defect, 3 = production-grade for an MVP-level design).

| Dimension              | What is checked                                                              |
| ---------------------- | ---------------------------------------------------------------------------- |
| requirementCoverage    | All explicit requirements are reflected; assumptions are marked              |
| serviceFitness         | Service choices are justified; nothing redundant or expensive without reason |
| connectionCorrectness  | Direction, semantics, protocols and integrations are correct                 |
| securityBaseline       | Auth, least privilege, private data not public, encryption                   |
| reliabilityOperability | Error handling, DLQs, observability, fault tolerance                         |
| costAwareness          | No obvious overspend; serverless/managed where appropriate                   |
| explanationAccuracy    | Rationale and connection descriptions are technically correct                |

**Critical defect:** any dimension scored 0, or any incorrect technical statement that would lead the user to an insecure or non-working solution.

**Defect severities:** `minor` (cosmetic or small improvement), `major` (a real weakness or wrong detail that a careful architect would fix before building), `critical` (see above).

**Documentation rule:** every `major` or `critical` defect must cite an official AWS documentation or Well-Architected URL in its `evidence` field. A claim you cannot support with documentation should be recorded as `minor`.

### Design A

**Requirements**

- R1 [functional, confirmed] Customer self-service portal consisting of a web app plus an API
- R2 [non-functional, confirmed] Protection against common web exploits and DDoS attacks
- R3 [constraint, confirmed] TLS everywhere (encryption in transit)
- R4 [constraint, confirmed] All data encrypted at rest with customer-controlled keys
- R5 [constraint, confirmed] Full audit trail of administrative API activity in the AWS account
- R6 [functional, confirmed] Customer sign-in with MFA
- R7 [constraint, confirmed] Application tier runs in containers in private subnets
- R8 [non-functional, inferred] Only approved, authenticated traffic reaches the app tier; no direct public exposure of private subnet workloads
- R9 [non-functional, inferred] Secrets and credentials managed securely rather than embedded in code or images
- R10 [non-functional, inferred] Centralized logging of application and access events for security monitoring
- R11 [constraint, inferred] Least-privilege access control for workloads and administrators
- R12 [non-functional, inferred] Application and database tiers remain available if one Availability Zone fails
- R13 [non-functional, inferred] Customer and account data can be restored after accidental deletion or corruption

**Containers** (tree)

- AWS Cloud (aws-cloud) [C1]
  - Bank-chosen Region (region) [C2]
    - Portal VPC (vpc) [C3]
      - Availability Zone A (availability-zone) [C4]
        - Public subnet A (subnet, public) [C6]
        - Private subnet A (subnet, private) [C8]
      - Availability Zone B (availability-zone) [C5]
        - Public subnet B (subnet, public) [C7]
        - Private subnet B (subnet, private) [C9]

**Nodes**

- **Retail customer** [N1] - EXTERNAL third-party: Retail customer
  - purpose: Signs in with MFA and uses the web app and API over the internet
  - rationale: Customers access accounts over the public internet from browsers and mobile devices
  - satisfies: R1, R6
- **Amazon Route 53** [N2] - service: Amazon Route 53
  - purpose: DNS for the portal domain
  - rationale: Routes customer requests for the portal domain to the load balancer entry point
  - placed in: AWS Cloud
  - satisfies: R1, R3
- **AWS Shield** [N3] - service: AWS Shield
  - purpose: DDoS protection for the public entry point
  - rationale: Shield Standard protects the internet-facing ALB and Route 53 against volumetric and protocol attacks
  - placed in: AWS Cloud
  - satisfies: R2
- **AWS WAF** [N4] - service: AWS WAF
  - purpose: Blocks common web exploits at the public entry point
  - rationale: Managed rule sets filter SQL injection, cross-site scripting and known bad inputs before traffic reaches the ALB
  - placed in: Bank-chosen Region
  - satisfies: R2, R8
- **AWS Certificate Manager** [N5] - service: AWS Certificate Manager
  - purpose: Issues and renews the TLS certificate for the portal domain
  - rationale: Provides public TLS certificates for the ALB listener so customer traffic is encrypted in transit
  - placed in: Bank-chosen Region
  - satisfies: R3
- **Application Load Balancer** [N6] - service: Application Load Balancer
  - purpose: Single HTTPS entry point routing web app and API requests to containers
  - rationale: Terminates TLS, requires Cognito sign-in for web app paths, and routes requests to the private container tasks; the only public ingress to the app tier
  - placed in: Public subnet A
  - configuration authorizer: Cognito user pool
  - satisfies: R1, R3, R8, R12
- **NAT Gateway** [N7] - service: NAT Gateway
  - purpose: Outbound internet access for private container tasks
  - rationale: Lets tasks in private subnets reach ECR and external services without accepting inbound internet traffic
  - placed in: Public subnet A
  - satisfies: R7, R8
- **Amazon Cognito** [N8] - service: Amazon Cognito
  - purpose: Customer user pool with MFA sign-in
  - rationale: Manages customer identity, password policy and MFA so the app does not store credentials
  - placed in: Bank-chosen Region
  - satisfies: R6, R11
- **Amazon ECS** [N9] - service: Amazon ECS
  - purpose: Runs and schedules the web app and API containers
  - rationale: Container orchestration for the app tier with service-level health checks and rolling deployments
  - placed in: Bank-chosen Region
  - satisfies: R1, R7, R12
- **AWS Fargate tasks** [N10] - service: AWS Fargate
  - purpose: Serverless container compute for the web app and API
  - rationale: Runs containers in private subnets without managing servers, reducing host-level exposure
  - placed in: Private subnet A
  - satisfies: R1, R7, R8, R11, R12
- **Amazon ECR** [N11] - UNRESOLVED service: Amazon ECR
  - purpose: Private registry for container images
  - rationale: Stores signed, scanned images so no credentials or secrets are baked into images
  - placed in: Bank-chosen Region
  - satisfies: R7, R9
- **AWS Secrets Manager** [N12] - service: AWS Secrets Manager
  - purpose: Stores database credentials and API secrets
  - rationale: Injects credentials into tasks at runtime and supports rotation, keeping secrets out of code and images
  - placed in: Bank-chosen Region
  - satisfies: R9, R11
- **AWS KMS** [N13] - service: AWS KMS
  - purpose: Customer-managed keys for encryption at rest
  - rationale: Bank-controlled keys with rotation and CloudTrail-logged key use satisfy customer-controlled encryption
  - placed in: Bank-chosen Region
  - satisfies: R4, R5
- **Amazon RDS** [N14] - service: Amazon RDS
  - purpose: Relational store for customer accounts and self-service data
  - rationale: Managed relational database in private subnets, encrypted with a customer-managed key and synchronously replicated across Availability Zones
  - placed in: Private subnet A
  - configuration backup: automated
  - configuration encryption: KMS
  - configuration multiAz: synchronous standby
  - satisfies: R4, R8, R12, R13
- **Amazon CloudWatch** [N15] - service: Amazon CloudWatch
  - purpose: Central logs, metrics and alarms for the app tier and security events
  - rationale: Collects container and access logs in one place for security monitoring and alerting
  - placed in: Bank-chosen Region
  - satisfies: R10, R11
- **AWS CloudTrail** [N16] - service: AWS CloudTrail
  - purpose: Records administrative API activity in the account
  - rationale: Provides the full audit trail of management API calls required for administrative accountability
  - placed in: Bank-chosen Region
  - satisfies: R5, R10
- **Audit and log archive bucket** [N17] - service: Amazon S3
  - purpose: Durable storage for CloudTrail logs and archived access logs
  - rationale: Private bucket with KMS encryption and versioning keeps the audit trail tamper-evident and recoverable
  - placed in: Bank-chosen Region
  - configuration backup: versioning
  - configuration encryption: KMS
  - satisfies: R4, R5, R10, R13

**Edges**

- Retail customer -> Amazon Route 53 (invoke, HTTPS): Resolves portal domain
  - satisfies: R1, R3
- Retail customer -> Application Load Balancer (invoke, HTTPS): Requests web app and API over TLS
  - satisfies: R1, R3, R8
- Retail customer -> Amazon Cognito (invoke, HTTPS): Signs in with password and MFA
  - satisfies: R6
- AWS WAF -> Application Load Balancer (other): Inspects requests before the ALB
  - satisfies: R2, R8
- Application Load Balancer -> AWS Fargate tasks (invoke, HTTPS): Forwards authenticated requests to tasks
  - satisfies: R3, R7, R8
- AWS Fargate tasks -> Amazon Cognito (invoke, HTTPS): Validates user tokens
  - satisfies: R6, R11
- AWS Fargate tasks -> Amazon RDS (invoke, TLS): Reads and writes customer data
  - satisfies: R4, R8, R11
- AWS Fargate tasks -> AWS Secrets Manager (invoke, HTTPS): Retrieves database credentials at runtime
  - satisfies: R9, R11
- Amazon ECR -> AWS Fargate tasks (other): Pulls signed container images
  - satisfies: R7, R9
- AWS Fargate tasks -> Amazon CloudWatch (other): Ships application and access logs
  - satisfies: R10
- AWS CloudTrail -> Audit and log archive bucket (write): Delivers audit trail logs
  - satisfies: R5, R10
- AWS Fargate tasks -> NAT Gateway (other): Outbound traffic to external services
  - satisfies: R7

### Design B

**Requirements**

- R1 [functional, confirmed] Customer self-service portal consisting of a web app and API
- R2 [non-functional, confirmed] Protection against common web exploits and DDoS
- R3 [non-functional, confirmed] TLS everywhere for data in transit
- R4 [constraint, confirmed] All data encrypted at rest with customer-controlled encryption keys
- R5 [non-functional, confirmed] Full audit trail of administrative API activity in the AWS account
- R6 [functional, confirmed] Customer sign-in with Multi-Factor Authentication (MFA)
- R7 [constraint, confirmed] App tier runs in containers placed in private subnets
- R8 [functional, inferred] What is the expected user scale and peak concurrent traffic for the portal? (decided by the architect)
- R9 [functional, inferred] Are there specific regulatory compliance frameworks the portal must adhere to beyond standard banking security? (decided by the architect)
- R10 [functional, inferred] What is the required availability target (SLA) for the self-service portal? (decided by the architect)
- R11 [non-functional, inferred] DNS resolution and global edge distribution for the web application
- R12 [non-functional, inferred] Load balancing for containerized application tier across private subnets

**Containers** (tree)

- AWS Cloud (aws-cloud) [C1]
  - Region (region) [C2]
    - VPC (vpc) [C3]
      - Availability Zone 1 (availability-zone) [C4]
        - Private Subnet 1 (subnet, private) [C6]
      - Availability Zone 2 (availability-zone) [C5]
        - Private Subnet 2 (subnet, private) [C7]

**Nodes**

- **Bank Customer** [N1] - EXTERNAL user: Bank Customer
  - purpose: End user accessing the portal
  - rationale: Represents the client accessing the application.
  - satisfies: R1, R8
- **Route 53** [N2] - service: Amazon Route 53
  - purpose: DNS resolution
  - rationale: Provides domain name resolution.
  - satisfies: R11
- **AWS Shield** [N3] - service: AWS Shield
  - purpose: DDoS protection
  - rationale: Protects against Distributed Denial of Service attacks.
  - satisfies: R2
- **CloudFront** [N4] - service: Amazon CloudFront
  - purpose: CDN and TLS termination
  - rationale: Delivers web assets globally with TLS termination.
  - satisfies: R1, R3, R10
- **AWS WAF** [N5] - service: AWS WAF
  - purpose: Web application firewall
  - rationale: Protects against common web exploits.
  - satisfies: R2
- **Amazon Cognito** [N6] - service: Amazon Cognito
  - purpose: Customer authentication
  - rationale: Handles user sign-in with MFA.
  - satisfies: R6, R9
- **Application Load Balancer** [N7] - service: Application Load Balancer
  - purpose: Load balancing
  - rationale: Distributes incoming traffic to containers across multiple availability zones.
  - placed in: Private Subnet 2
  - satisfies: R10, R12
- **Amazon ECS** [N8] - service: Amazon ECS
  - purpose: Container orchestration
  - rationale: Runs application containers in private subnets.
  - placed in: Private Subnet 1
  - satisfies: R1, R7, R8
- **AWS KMS** [N9] - service: AWS KMS
  - purpose: Encryption keys
  - rationale: Provides customer-managed keys for encryption at rest.
  - satisfies: R4, R9
- **AWS CloudTrail** [N10] - service: AWS CloudTrail
  - purpose: Audit logging
  - rationale: Captures audit trail of administrative API activity.
  - satisfies: R5, R9
- **Amazon CloudWatch** [N11] - service: Amazon CloudWatch
  - purpose: Observability
  - rationale: Collects logs and metrics.
  - satisfies: R5

**Edges**

- Bank Customer -> Route 53 (other, HTTPS): DNS Query
  - satisfies: R11
- Bank Customer -> CloudFront (invoke, HTTPS): HTTPS Traffic
  - satisfies: R1, R3
- CloudFront -> AWS WAF (other, HTTPS): WAF Inspection
  - satisfies: R2
- CloudFront -> Application Load Balancer (invoke, HTTPS): Origin Traffic
  - satisfies: R1, R3
- Application Load Balancer -> Amazon ECS (invoke, HTTP): Route to Containers
  - satisfies: R1, R7
- Bank Customer -> Amazon Cognito (invoke, HTTPS): Auth with MFA
  - satisfies: R6
